# ScholarLite 重排诊断与改造方向

日期：2026-10-30。范围：代码、当前运行界面、用户截图、两篇原 PDF 的只读重解析和成熟方案调研；没有修改产品实现或用户书库。

## 结论

这是**文档结构恢复与质量验收失效**，不只是图片高度、字号或 OCR 模型不够好。当前管线把二维文档过早分解成行和段落，分类错误又成为裁剪的硬边界。最终输出即使含有负高度裁剪框、公式碎片、作者信息，也能被当成新版成功结果保存。

首选方向是保留现有 PDF.js 原稿渲染、阅读器与笔记能力，重做中间文档结构和发布判据，并接入成熟布局提取器作候选。先保证内容完整、归属正确，再提高 LaTeX 与文本重排比例。

## 算法与作者信息：实现支持范围比界面承诺窄

`algorithms.ts:38–61` 从长度至少为正文字号 10 倍的横线开始，要求附近有 `Algorithm/算法 + 数字` 标题，且存在左右端点都对齐（误差小于 3 pt）的底线，最后才检查行号、输入输出和控制语句。`identifyCodeFigures` 同样先要求上下横线。没有边框就没有候选入口；跨页算法也没有跨页节点。对于已支持的有边框伪代码，这是保守保护；但它不能承担“所有算法都能识别”的契约。应增加独立算法区域候选及跨页关联，未可靠解析时完整保留缩进/行号/数学的原稿区域，而不是落回散文。

作者段落漏检也有具体原因：`reading-roles.ts:39–42` 的起始句要求学位或某些职业句式；`:82–83` 的续段前缀包含 `Dr.`，却不含 `Mr.`。`Mr. Wen received…Award…` 因而既不满足学位起始句也不满足续段；`Dr. Perez obtained…Habilitation…Privatdozent…` 虽有 `Dr.`，却不含 `PERSONAL_DETAIL` 词表所列的关键词，同样退出传记状态。

头像检测在 `portraits.ts:24–26` 又独立要求相邻 `received` 句及特定学位缩写。ReFFT 最后一位作者是 `Dr.-Ing.`，不在其学位正则内；该头像继续成为普通 figure。这里需要让头像、姓名、学位/任职/获奖段共享同一个作者区身份，消除文本分类和头像分类之间的两套不一致规则。

图注同样受字体阈值限制：`analyze.ts:690–694` 即使已识别 `Fig. N:`，通常仍要求字号小于正文的 95%，除非是空标题或特定 code figure。SWCS Fig.1/2/3/5 的源字号均为 9.963，落成 p；Fig.4 为 8.966，才落成 caption。应根据图注标记、位置、对应图形和上下文建立关系，字号只作为辅助证据。

## 原稿回退也会出错：截图 12 的具体路径

SWCS p5 ord194 文本以控制字符 U+0004 开头。`analyze.ts:585–587` 遇到未知字形会为整个文本块设置 `sourceTextFallback`，用其文本 bbox 加 2 pt 作为截图区域。

`Reader.tsx:1007–1015` 将这种正文交给 `FigureBlock`，并将显示 kind 设为 figure。`FigureBlock.tsx` 用裁图宽度除以固定 9 得到 em 宽度；`styles.css:139–140` 再把图片限制在容器宽度内。它没有普通段落的重排行为，也没有使用该块的 `sourceFontSize=9.963`。截图中出现的原稿字体、邻行残片与边缘截断需要在这一条链路处理。

正确方向是对未知字形进行局部、可溯源的回退；必须整段保真时，使用专门的文本保真区域渲染器和完整区域边界，而不是让正文冒充普通插图。行内数学、列表组合字形（例如圈号）、无法映射的符号也应分别建模。

## 为什么多次修复仍然漏

1. **局部规则相互反馈。** `math.ts:59–61` 用英语词数/数学字体比例判定 prose，将小字号英语下标判成正文；`:166` 因此停止区域扩张，`:108–113` 又以其顶端限制公式底部。对 Eq.(8)/(13)，裁剪底部甚至高于公式主行基线。只在内存中修改这一判定后，目标下标重新归属且两个反向 crop 消失，但相邻公式又出现 33 个重复归属字形。这个反事实实验说明必须同时修复区域归属，不能再单改词数阈值或 padding。
2. **“调用成功”被当成“内容成功”。** `App.tsx:319–327,360–367` 在解析返回后直接保存；`electron/db.ts:489–568` 有事务与笔记重锚，但没有拒绝无效裁剪框、公式泄漏或缺内容的质量门。事务保证一次写完，不保证写进去的东西正确。
3. **显示回退依赖同一份可疑边界。** OCR/结构失败以后回到原稿是对的，但裁图边界本身若错，回退仍是坏图。
4. **文档角色过于局部。** 作者学位句、任职句、获奖句和头像共同组成作者区，不能只靠每段是否命中特定短语决定隐藏。
5. **旧验收不能证明新论文质量。** `VALIDATION.md` 中有特定样本和合成测试的通过记录；`.work/robustness-20261030/QA.md` 的 10 篇/104 页完整逐页验收仍全部写为“未验收”。不能把解析执行成功、块数稳定或少数公式正确当成全库排版达标。

本轮公式审计实际运行了 `math-crop-ownership`、`crop-regression`、`reflow-regression`（42 项）、`inline-reflow`、`formula-structure`（9 项），全部通过；同一源码对用户论文的失败仍可稳定复现。测试有价值，但此前没有把这些真实失败条件纳入判据。

## 建议的结构边界

```text
PDF 原页 + 原生 glyph/drawing/image 与坐标
  → 文档/页面结构候选：栏、段、公式、算法、图表、图注、作者区、页眉页脚
  → 区域关系与内容归属：父子、captionOf、continues、readingOrder
  → 原文/数学结构提取；保存原页、区域与原始元素的来源关系
  → 阅读投影：隐藏作者区与页面装饰，保留元数据和原稿笔记定位
  → 质量门：通过才发布；局部不确定区域采用完整原稿保真显示
  → React 重排与可选 LaTeX、翻译、检索
```

不要先做一个庞大通用文档平台。现有 `Block` 继续作为阅读投影；新增最少的区域身份、来源元素归属、复合关系和验证状态，解决本次实际失效即可。跨页算法/长公式需要多个 page-region 指向同一个语义节点，不应硬塞进一个单页 crop。

作者信息按阅读策略隐藏：首页作者、机构、通信作者，尾部简介、获奖/任职段落与照片；书库作者元数据、原 PDF、原有批注仍保留。参考文献、技术附录、资助说明分别归类，不能以“参考文献之后全删”代替作者区识别。

## 发布前必须守住的判据

- 裁剪框有限且正面积，页坐标一致；识别框、显示框均验证。负高度不是可降级正常输出。
- 公式/算法先成为完整复合区域；正文不得出现已归属区域的碎片。视觉内容只显示一次，提取文本可作为同一区域的辅助表示。
- 公式区不仅包含基线文字，还覆盖分数线、求和上下限、伸缩括号、重音、编号和连续公式行；不能把看似英文的下标当独立 prose 边界。
- 关键内容有明确去向：重排文本、原稿保真区域或明确隐藏的页面装饰/作者信息；不得静默缺失。对扫描页，使用图像区域覆盖与人工标注，不伪造不存在的 glyph 证据。
- 正文、图注、算法角色由结构证据确定，显示字号不反向决定语义。
- 原稿回退也接受完整性检查；失败时扩大到安全的栏/页区域，并明确提示该局部保真显示，而不是展示半个公式。

## 成熟方案：首个候选选 MinerU，结构设计参考 Docling

优先验证 **MinerU 4.1.2 Standard 本地路线**，消费 MiddleJson 与图片 assets，不把 Markdown 再拆回不可靠段落。其现有 renderer 可作为对照，PDF 重排需要显式 `REFLOW`，默认 AUTO 可能保持原布局。Apple Silicon 有 Torch/MPS 与 llama.cpp/Metal 路线；本机 M4/16 GB 的实际峰值内存与解析时间仍需用这组样本测量。[输出契约](https://opendatalab.github.io/MinerU/reference/output_files/)、[本机运行路径](https://opendatalab.github.io/MinerU/usage/tiers/)

**Docling 是优先对照，也是中间结构的参考**：区分 body 与 furniture，保留文档层级、bbox、provenance 和顺序。其不同 PDF/VLM 管线的数学能力不一样，不能用某个 enrichment 开关概括全部能力。[DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/)

GROBID 更适合论文元数据/引用结构，不作复杂数学恢复主干；Marker 和 Nougat 的实际模型许可有额外限制，不作为本轮默认依赖。MinerU 在 Mac 上默认量化模型包的授权链也应在正式分发前补齐。细节与原始许可链接见成熟方案报告。

## 多模型意见与取舍

- **GPT-6.1-Sol / ultra**：负责官方文档/源码调研，优先验证 MinerU Standard、Docling 对照。
- **GPT-6-Astra / ultra**：负责当前源码与真实 PDF 的公式复现；定位错误 prose 边界，并证明单点放宽会产生新的重复归属。
- **本机 Claude Code，Claude Fable 5.1 / max**：完成无工具的架构质疑。CLI 返回的 modelUsage 确认为 `claude-fable-5-1`，原始判断保存在 `.work/reflow-audit-20261030/claude-fable-review.json`。它建议先解决确定性几何、归属和验收问题，外部模型要证明净收益后再接入。

另启动过本机 Opus 辅助只读审阅（CLI 记录实际为 Opus 5.5、请求 max）；交付收敛时停止，未获得最终意见，不计为已完成评审。状态保存在 `.work/reflow-audit-20261030/claude-opus-status.json`。算法与作者规则的上述结论由主审计直接核查源码和实际输出，不归于该未完成请求。

我的取舍是：**先补共同结构契约和质量门，同时把成熟引擎作为可替换候选，而不是把它当真值，也不继续把自制启发式当唯一长期路线。** 引擎负责提出结构候选；产品层负责可溯源的区域归属、原稿保真、阅读策略和发布检查。

采用 Fable 关于 glyph 之外还要考虑矢量 path 和 image 的提醒；不采纳“所有像素零残差”“裁掉其他单元墨迹”“语义阶段永远不得修正归属”作为普遍硬规则：PDF 存在重叠绘制、背景、字形包围盒误差，机械排除其他框会重新截断公式；角色纠正也可能需要重算区域。应检查有效内容元素的归属、明确的包含/冲突关系与金标区域覆盖，允许复合节点包含子区域，但最终阅读不能重复显示内容。

不需要先建通用语义图谱，也不需要现在扩到二三十篇全量验证。当前两篇失败 PDF、明确算法样本和既有通过样本足以启动第一轮，扩样应由新的版式风险驱动。

## 下一轮实施顺序

1. **固定失败判据。** 本轮已完成两篇 fresh parse、7 项红色验收、公式原图/当前裁图对照及根因探针。
2. **修复共同底层。** 源元素归属与复合区域先于正文分段；生成/保存前拒绝非法边界；作者区整组分类；文字回退使用正确的局部边界和显示组件。保持笔记锚点、人工确认公式及原 PDF。
3. **验证外部候选。** 获得新依赖/模型安装授权后，在隔离环境用相同故障页运行 MinerU Standard，记录实际内容质量、首个可读页时间、峰值内存。若有明确质量或部署问题，再用 Docling 对该问题做针对性对照。无需同时维护五种后端。
4. **按证据迁移。** 候选通过原稿对照与阅读器关键交互后才替换对应解析路径；删除被替换的重复逻辑，避免两套规则同时争抢同一块内容。局部不确定时保真显示完整原稿区域，不以残缺内容冒充成功重排。

完成条件：用户指出的公式、行内数学、算法、图注、作者信息问题在实际阅读器和新旧缓存切换中通过；原有正确内容和笔记可用。外部引擎尚未在这两篇实跑，当前结论是架构与候选选择，不是修复已完成。
