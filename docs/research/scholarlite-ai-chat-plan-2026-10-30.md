# ScholarLite：论文 AI 对话接入方案

调研日期：2026-10-30。范围：承接原对话、只读检查当前项目与本机 CLI、分析交互与架构；未实施 AI 功能，未发起模型请求。供应商的一方资料与 T3 Code 源码证据见 [本机 Agent 调研](local-agent-providers-2026-10-30.md)。

## 建议方向

在现有右侧面板增加「AI」标签，使用 Electron 主进程管理的本机 Agent 进程。前端自有聊天界面，应用保存结构化消息、附件和论文来源，供应商适配器负责会话、流式事件、停止与能力发现。

先用 Codex App Server 做出完整阅读对话链路，再接 Claude Code；其他 Agent 按实际协议和能力逐个扩展。阅读交互与 Agent 后端分离，翻译保持自己的配置与调度。

供应商选择已经核实：T3 Code 的 Codex 后端采用 App Server，Claude 后端采用官方 Agent SDK。ScholarLite 的 Claude 长期实现也推荐 SDK streaming input，并指定本机原版 Claude Code；CLI 双向 stream-json 仅在明确需要不新增 SDK 依赖时作为替代实现，不保留两套长期控制协议。其他 Agent 先考虑 ACP，再按实际能力扩展。源码、官方接口及当前用户自行登录的订阅使用条件均见供应商报告。

“本机 Agent”指由本机启动并复用其支持的登录和配置；模型是否在云端运行、如何计费，取决于该 Agent 的实际后端。已安装 CLI 不等于已经验证登录可用。

## 用户看到的交互

1. 在截图标记处排列「笔记 / 大纲 / AI」。点击 AI 打开同一个右侧辅助面板；对话列表、正文、输入框在面板内部。AI 模式建议初始宽度约 420px，允许拖动，窄窗口收起左书库或提供展开阅读模式；普通笔记保留较窄宽度。
2. 选中文字后，浮动工具条增加「问 AI」。右键另提供用户明确要求的「发送给 AI 解读」与「引用到 AI」。右键打开前捕获选区快照，菜单夺焦不能丢掉内容；不能假定现有鼠标松开事件覆盖右键和键盘选区。
3. 「发送给 AI 解读」直接提交含引用卡片的解释请求；「引用到 AI」仅放入输入框，可继续写问题。显示论文名、页码、选中文字及原文/译文标记，允许展开与移除。
4. 图片支持粘贴、拖放、文件选择；论文图表、公式预览也提供「发给 AI」。展示缩略图、移除按钮和上传/准备状态；图片以真正的视觉输入交给支持图片的模型，不能只发文件名。
5. 回答支持流式 Markdown、公式、列表和代码；支持复制、停止、重试、编辑后重发、新建/切换对话、引用某条消息或其中一段继续追问。编辑历史问题及重新生成形成分支，旧回答可查看。
6. 论文引用点击返回页码/段落；AI 消息引用点击回到被引消息。两类引用分别建模。支持把选中的回答保存为现有笔记。
7. 对话默认属于当前论文，每篇可有多个会话。切论文恢复该论文的历史和草稿；切标签、收起面板不取消回答。运行状态可在当前论文之外显示标记，不能把返回结果写到新打开的论文中。

界面沿用 tokens.css 的材质、圆角、字体、动效和 reduced-motion 规则。长回答保留可读字号，AI 模型/Agent 选择放输入区附近，路径与连接诊断放设置。

## 模块边界与数据

```text
Reader / 图表预览 / ChatPanel
             ↓ 明确的 chat IPC
ChatService：消息、论文上下文、附件、运行状态与持久化
             ↓ Provider 接口
Codex App Server | Claude Code | 其他适配器
             ↓
本机安装的官方 Agent → 用户所配置的模型服务
```

建议代码职责：

- `shared/chat-types.ts`：消息 parts、来源锚点、能力、运行状态、事件。
- `electron/chat/service.ts`：运行与恢复；`store.ts`：SQLite；`attachments.ts`：附件；`context.ts`：论文上下文。
- `electron/chat/providers/`：每家 Agent 的协议与进程生命周期。
- `electron/chat/ipc.ts` + preload：固定命令及事件订阅。
- `renderer/src/chat/`：ChatPanel、消息、输入框、引用卡片、历史与状态；ReadingPanel 统一持有顶层标签。

不用把每个 token 放进 App.tsx 的顶层 state。App 负责当前论文与面板选择；chat store 负责逐会话订阅和更新。现有 Reader 与 NotesPanel 会按论文/解析版本 remount，运行状态必须归主进程服务所有。

推荐持久化实体：Conversation（paperId、标题）、ProviderSession（供应商、实际模型、远端会话 ID）、Message（父消息、分支、角色、parts）、Run（状态与错误）、Attachment、SourceReference。应用消息是用户历史的主记录，ProviderSession 是执行记忆与恢复映射。

同一会话串行运行；不同论文可有独立运行，但进程数量需要有界。事件带 conversationId / runId / itemId / seq，最终状态与部分内容一致落库，IPC 订阅只向有权访问的渲染窗口分发。进程退出将未完成消息标记为中断，保留已生成内容，恢复时不自动重复提交。

消息 parts 至少区分 text、image、paperReference、messageReference。论文来源保存 paperId、page、blockIds、原文快照、展示语言、可用的每段偏移/坐标及解析版本。跨段引用应保存每段片段；当前 Selection 的单段 start/end 不能直接承担全部来源信息。选中译文时单独保存译文和对应原文，不能把译文偏移当作原文偏移。

重新解析后先匹配同页原文及坐标；唯一命中再恢复段落跳转，无法可靠匹配时退到页码并保留快照。禁止仅因旧 blockId 存在就跳到它。

切换 Agent 时新建 ProviderSession，以用户可见的消息与来源构建接续上下文。旧供应商的隐藏会话记忆不能直接转移；历史不得因此清空，也不能提示为同一原生会话无缝恢复。

## 上下文：先把当前论文用好

首轮默认发送问题、选区、所在段落、必要邻段/小节标题、论文信息和显式图片。输入区显示「选区」或「当前论文」范围；后续消息复用 Agent 会话，增加本轮新来源。

“当前论文”问答应基于现有 blocks 构建按页/章节组织的材料。小论文可在预算内直接加入全文；超出预算时明确告知范围并提供章节选择或受控的论文读取/检索工具。用户明确要求通读全文时，要覆盖全文或说明尚未读完哪些部分，不能用少量检索结果冒充通读。

首版不引入向量数据库：单篇论文已有结构化文本，先用章节组织与普通文本检索。跨论文检索是后续独立能力。切换论文不向旧会话偷偷注入新论文。

回答中可点击的论文来源由应用给出的来源 ID 解析为结构化链接；不把模型随口生成的页码自动认作可靠引用。来源定位准确与科学解释正确分别验收。

## 本机进程与工具权限

Agent 只由主进程通过 spawn/execFile 启动，参数数组传递，正文走 stdin/协议消息；渲染层不提供任意 shell 执行接口。默认 stdio 通信，不需要另起公网后端。macOS Finder 启动的 PATH 可能不同，设置应支持探测标准安装目录和用户选择可执行路径，保存绝对路径。

附件复制到应用控制的持久目录并分配 ID，保留 MIME、尺寸、来源；校验真实类型、大小和解码结果。Blob URL 仅用于预览，不能作为 Agent 的持久附件路径。模型或供应商不支持图片时在发送前明确反馈。

论文解释模式默认只开放必要的论文资料能力；复用登录不等于继承全部 hooks、MCP、skills 或文件写入权限。工作目录使用应用管理的会话目录，不能设成用户 home 或项目源码目录。Codex 采用受限读取根目录；Claude 使用明确工具集合与受控配置。论文正文和模型输出按资料处理，不能因此授权运行命令。需要更广研究工具时再按动作展示和处理审批。

聊天 Markdown 默认禁用原始 HTML、校验链接协议；附件访问通过受控 ID。已有 KaTeX 可复用，Markdown 渲染依赖在实施时选择成熟方案；本次没有安装依赖。

## 实施顺序与完成条件

1. **Codex 完整闭环**：AI 标签、Agent 探测与连接状态、会话/消息保存、双向流式协议、重排文字右键解释、图片消息、停止与恢复、两类引用及跳回来源。先证明真实视觉输入与跨轮会话都工作，再扩展界面功能。
2. **日常使用与 Claude**：Claude 官方程序化接口、模型/能力发现、草稿、历史、编辑/重生成分支、保存笔记、原页 TextLayer 与选区/截图。完成所有已承诺阅读模式的交互，不把原页选区缺口遗漏。
3. **其他 Agent 扩展**：按用户实际使用对象实现 ACP 或厂商接口，逐项探测图片、恢复与工具能力。跨论文研究另行规划，避免混入本次阅读聊天的验收。

将来实施的定向验收包括：跨段/译文/右键选区；图表真图输入；两轮追问；停止无后台续写；切论文不串消息；重启恢复；解析后来源定位；图片不支持/登录失效/进程退出的真实错误；浅深主题、窄窗口与 Markdown/公式可读性。模型真实请求和新增依赖遵循届时授权。本轮没有运行应用测试或改变在用 GUI。

实施时同步更新 README 与 package.json 中历史的「不含 AI 问答」声明，保持文档与产品一致。
